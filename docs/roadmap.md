## Output modes (§1)

- `[x]` **Portable Image SVG** — production mode (embedded raster + native SVG annotations + metadata).
- `[~]` **Hybrid editable SVG** — `src/lib/capture/hybrid.ts`: `snapshotDom` snapshots the demo page's live DOM at capture time (per-element bounds + computed styles, self-contained raster-fallback crops for canvas/video/iframes/filters/transforms/external images), `buildHybridSvg` converts supported elements to native vector `<rect>`/`<text>`/`<image>` and layers the same annotations + metadata as the portable path, and `summarizeSnapshot` emits the machine-readable export report (per-region representation + fidelity, §15/§28). Scoring: ≥90 simple-vector, 60–89 complex-vector, <60 rasterized. Gradients and shadows are native SVG where parseable: `linear-gradient`/`radial-gradient` (incl. keyword angles + rgba/hsl stops) → `<linearGradient>`/`<radialGradient>`, single spread-less `box-shadow` → `<feDropShadow>`; conic/image/`var()` backgrounds, inset/spread/multi shadows → raster fallback. Multi-line text uses **measured browser line boxes** (blueprint §15 — one `<text>` per measured line at its exact position, no re-wrapping; `findLineBreaks` binary-searches real `Range` rect tops, capped at 4k chars/element). Clipping is native SVG where parseable: `clip-path: inset/circle/ellipse/polygon` → `<clipPath>` defs (userSpaceOnUse, percentages resolved against the node), rounded images are clip-rounded, and `overflow: hidden/clip` parents wrap their children in a clip group. Semantic **landmark `<g>` boundaries** (blueprint §15): the snapshot keeps `parentId` + ARIA landmark roles (`semanticRoleOf` — explicit roles win, header/footer excluded inside article/aside/main/nav/section, section needs an accessible name), and `buildHybridSvg` rebuilds the DOM tree so each landmark opens `<g id="region-…" data-role="…">` (unique ids when the role repeats) with its subtree nested inside — no class names or framework ids leak into the file. Basic transforms: computed CSS `transform` (parseable `matrix(...)`/`matrix3d(...)` — plain translate/rotate/scale, nonzero skew, or any mix) → native SVG `transform="matrix(...)"` on the emitted vector node, so rotated/scaled/translated text and shapes stay fully editable (unparseable/`var()`/`calc()`-heavy or 3D-perspective transforms still fall back to raster). Exported from the Export tab as **Hybrid SVG** / **Hybrid report** (demo captures only — URL captures have no DOM access).
- `[ ]` **Native-vector (experimental)** — must be labeled experimental.

## A. Capture modes & strategies (§5, §12)

- `[x]` **Element capture mode** — CSS selector on the built-in demo page; rect resolved from the live DOM and rasterized via translate-crop. URL captures are blocked with a clear message (no remote DOM access).
- `[x]` **Region capture mode** — rectangle in page coordinates; cropped from a translate-rendered region in the demo, or cropped from the remote full-page render for URLs.
- `[ ]` **Multi-region / responsive / step-sequence modes** — request-level modes exist in the blueprint but not in the type/model.
- `[ ]` **Capture strategy selector** — discovery result should choose direct / tiled / element / region automatically.
- `[ ]` **Horizontal scrolling** capture.
- `[ ]` **Nested scroll containers** capture.

## B. Scrolling, freeze & page handling (§9–§11)

- `[~]` **Lazy-content loading** — demo stage + extension full-page (Phase C) both load lazy content incrementally (stepRatio 0.8, maxPasses 40, maxHeight 100k); the URL path delegates to the capture service.
- `[ ]` **Infinite-scroll detection with user choice** — the engine stops at limits and warns; blueprint requires offering *capture loaded content / capture N px / viewport only / cancel*.
- `[ ]` **Virtualized-content detection** — repeated rows, constant child count, transform reuse; tile each visible section.
- `[x]` **Fixed/sticky element strategy** — extension Phase C implements capture-once/hide-later (headers tile 0, footers last tile, sticky hidden while stuck); the in-app demo pipeline captures a single rendered canvas, so no strategy is needed there.
- `[~]` **Freeze beyond CSS/video** — the extension freezes CSS animations/transitions/carets and pauses video (Phase C); animated GIF/SVG, canvas/WebGL rAF loops, carousels, clocks still aren't actively frozen (compositor-level capture renders their current frame regardless).
- `[ ]` **Tainted canvas/WebGL fallback** — detect unreadable canvases and capture the compositor frame instead.
- `[x]` **Page restoration on failure** — the extension restores scroll position, freeze stylesheet, fixed-element classes, and video state in a `finally` block even when the capture fails or the popup closes (Phase C); the demo stage remains disposable.

## C. Tiled stitching (§13)

- `[x]` **Tiling** — demo pipeline slices one canvas into `<image>` tiles (MAX_TILE_HEIGHT 4000).
- `[ ]` **Overlap + seam matching** — tiles are exact slices today; extension tiles will need overlap, MAE/SSIM comparison, retry on mismatch, unstable-seam reporting.
- `[~]` **Extremely-tall-page output options** — split into multiple SVGs shipped (`sliceDocumentForExport` + ZIP download, 16,000px per slice, `overflow:hidden` seam clipping); a combined **capture set** remains.

## D. Editor (Phase 3)

- `[x]` Tools: select, arrow, rectangle, text, callout, step marker, highlight, mask.
- `[x]` **Crop** tool — destructive base-crop; tile-aware pixel crop (`cropDocument`), annotations outside the crop dropped, undo history cleared.
- `[x]` **Blur** tool — real SVG `feGaussianBlur` filter (serialized, parsed back, sanitizer-allowed), adjustable radius.
- `[x]` **Secure redaction** — destructive: source pixels are replaced in the raster itself (`applyPixelRedaction`) and verified via before/after pixel hashes; intersecting annotations removed; `redacted`/`redactions` audit trail on the document + sidecar; undo cleared; the validation integrity hash is recomputed on the next run. (Raster-only v1: DOM-text/OCR-text/metadata removal is N/A because the base capture is a raster — those become relevant with Hybrid SVG + OCR.)
- `[x]` **Magnifier** annotation — a circular loupe that re-draws the base capture at 2–4× inside the lens (clipPath + scaled `<use href="#base-capture">`, crosshair + zoom label), serialized/parsed like the other annotations.
- `[x]` **Layer reorder / duplicate / group / flatten** — reorder + duplicate + shift-click multi-select; **grouping** tags members with a shared group id (survives the SVG round-trip via `data-group`) and **flatten** removes the tags; both are plain undoable annotation edits.
- `[x]` **PDF export** — dependency-free single-page PDF (JPEG DCTDecode), scaled to PDF points.
- `[x]` **Editable project file (.vcap)** — separate from the published SVG; the base layers, annotation model, metadata **and undo/redo history** are persisted (`src/lib/capture/project.ts`, format `stitap-project` v1) so captures can be re-edited after reopening (§14).

## E. Documentation intelligence (Phase 5 — on-device NLP layer, see `docs/nlp-layer.md`)

- `[x]` **OCR service** — on-device tesseract.js (v7, ≈15MB `eng` traineddata — the smallest practical in-browser OCR) over capture tiles with confidence + coordinates (§16); merge/offset helpers; "Extract text" in the Intelligence tab. Model-free DOM text extraction exists as a helper (`extractVisibleText`) but is not yet stored in the project.
- `[x]` **OCR-at-capture** — OCR runs inside the engine's processing stage and persists `ocrLayers` on the capture document (§14) instead of on-demand in the Intelligence tab. Two producers: demo captures extract text instantly from the live-DOM hybrid snapshot (`ocrStateFromDomSnapshot`, engine `hybrid-dom` — no model); raster-only captures run on-device tesseract per tile (`runOcrAtCapture` → `ocrStateFromBlocks`). Capped at 1500 layers / 20k chars; `status: "failed"` degrades to a warning without blocking the job. Survives the SVG round-trip (`vc:ocrStatus`/`vc:ocrEngine`/`vc:ocrBlockCount`/`vc:ocrText` metadata) and the JSON sidecar (`ocr`), is restored by `documentFromSvg`, and feeds suggested alt text, library search, and the sensitive-data scan. Request toggle: “Extract text at capture time” (`intelligence.ocrAtCapture`, default on). The Intelligence tab now shows the persisted capture-time text instantly and offers “Re-run OCR on raster”.
- `[x]` **OCR accuracy upgrade (optional)** — two-stage STR swap-in behind `nlp.ocrImage({ strategy: "str" })`: stage 1 is pure projection-based line-box detection (`detectTextSegments` in `src/lib/nlp/str-layout.ts` — edge-energy projection, solid-block rejection, wide-line chunking; polarity-agnostic so dark themes work); stage 2 recognizes each crop with `onnx-community/mgp-str-base` (61M, q4 ONNX ≈91MB via Transformers.js). Falls back to tesseract automatically if the model can't load. “Fast / Accurate” toggle in the Intelligence tab (default tesseract ≈15MB).
- `[x]` **DOM text extraction** — the hybrid snapshot's measured text nodes/lines become OCR layers at capture time (`ocrStateFromDomSnapshot`); `extractVisibleText` remains for on-demand use.
- `[x]` **Sensitive-data detector** — regex + on-device distilbert-NER fusion (`nlp.detectSensitive`); scans metadata, annotations, and OCR text from the Intelligence tab. The engine's URL-query warning (`security.ts`) still runs at capture time.
- `[x]` **Suggested alt text** — on-device distilvit captioning with a heuristic fallback; "Use as description" fills metadata.
- `[x]` **Step-guide generation** — deterministic template + optional Qwen2.5-0.5B @ 2-bit polish (wllama), markdown copy/download.
- `[x]` **Search index** — semantic library search: on-device embeddings (MiniLM or rule fallback, 384-dim) with an ensure-index pass, ranked server-side by the Convex native vector index (`captures.by_embedding`, 384-dim, `userId`-filtered — `searchByEmbedding` action) with a client-side cosine fallback; index text now includes capture-time OCR text; text mode also matches OCR text.
- `[x]` **Error explanation** — `nlp.explainError`: instant code-keyed catalogue (`ruleExplainError`, covers every engine code) + capability-gated on-device instruct model (Qwen2.5-0.5B @ 2-bit ≈ 415MB via wllama) for unknown codes; "Explain this error" / "Explain in detail" buttons on the job panel.
- `[x]` **Mistake review** — `nlp.reviewMistakes`: pure checks (typos, duplicates, numbering, length, markdown) + optional model pass; "Check for mistakes" on step guides.
- `[x]` **Device capability gating** — `capability.ts` (pure): legacy (<2GB RAM) → rule-only, standard (2–4GB) → 415MB model, modern (≥4GB/WebGPU) → full. Honest rationale documented: native 1.58-bit GGUFs are 1.2–2.2GB on HF, too big for 2GB machines.
- `[x]` **Vision feedback** — `nlp.visualFeedback`: deterministic structural review (`ruleVisualFeedback`) on every device + optional on-device VLM (Qwen2-VL-2B @ IQ2_M ≈ 900MB via wllama, gated by `visionCapability`); "Review structure" / "Visual review" in the Intelligence tab. Qwen2.5-0.5B is text-only — true 1.58-bit VLMs don't exist yet on HF.
- `[x]` **Capture replay** — `src/lib/capture/replay.ts`: `buildCaptureRecipe` / `buildReplayScript` generate a deterministic Playwright script (viewport, readiness, lazy scroll, mode-specific screenshot) from the capture document; "Replay script" export re-captures any future version — capture once, refresh per release.
- `[x]` **Secret replay (encrypted SVG metadata)** — `src/lib/capture/crypto.ts`: the visible SVG stays a plaintext picture while the replay recipe JSON (URL, viewport, mode, selector, readiness — the Playwright script source) is encrypted with AES-256-GCM under a PBKDF2-SHA256-derived passphrase key and embedded in a `data-secret` attribute on the invisible `<metadata>` element. `embedSecret`/`extractSecret` are pure string ops (survive sanitization + Bun tests); the key is never stored on disk. "Encrypted SVG" export prompts for a passphrase; "Unlock replay" reads any such file back and regenerates the spec. Note: the URL also appears in plaintext metadata while "Include source URL" is on — toggle it off for full URL secrecy.

## F. Security, validation & hardening (§21–§22, Phase 7)

- `[x]` **SSRF guard** — scheme allowlist, private-network blocks, custom ports allowed, and **redirect re-validation**: the URL capture action walks each redirect hop with `redirect: "manual"` and re-runs the same checks on every `Location` (`validateRedirectTarget`, max 5 hops) before the capture service follows it. Remaining: IDN/domain normalization.
- `[x]` **XML security validator** — explicit DTD / external-entity guard: `xmlSecurityIssues` (pure string scan for `<!DOCTYPE`/`<!ENTITY`/`<!ELEMENT`/`<!ATTLIST`/`<!NOTATION` + external `xml-stylesheet` PIs) fails the sanitizer loudly and adds a `no-dtd` validation check.
- `[x]` **Resource validator** — validation now enforces ≤ 5,000 embedded images and ≤ 30 MB embedded bytes.
- `[~]` **Visual comparison engine** — the Hybrid report (`summarizeSnapshot`) provides per-region fidelity scores (high/medium/approximate) and a rendering-confidence estimate; pixel-level diff against the source capture is not yet implemented.
- `[x]` **Integrity generator** — SHA-256 checksum in the validation report (recomputed after any destructive edit).
- `[x]` **Authorization/permission UI (§5.3)** — policy engine enforces domain allowlists and capture policies at the engine level; the Policy Config and Audit Log HTTP endpoints and Tauri IPC commands make these inspectable; UI integration via Settings panel (domain rules display, capture policy config, audit log viewer).
- `[x]` **Policy engine** — domain allowlists (`engines/src/policy.rs`: glob + exact + TLD patterns, last-match-wins evaluation, allow/block actions), capture policies (format/viewport/height/sandbox-per-URL restrictions), retention policies (age/count/storage-based auto-delete with archive option), and org presets. Policy config serialises via the in-repo JSON module (zero crates). HTTP endpoints: `GET /v1/policy/config`, `POST /v1/policy/check`, `POST /v1/policy/validate`, `GET /v1/policy/audit`, `GET /v1/policy/audit/summary`, `POST /v1/policy/audit/record`. Tauri IPC: `policy_config`, `policy_check_url`, `audit_summary`, `audit_entries`. Frontend: `getPolicyConfig()`, `policyCheckUrl()`, `getAuditSummary()`, `getAuditEntries()` in `desktop.ts`.
- `[~]` **Export report** — the **Hybrid report** (`summarizeSnapshot`, “Hybrid report” button in the Export tab) already emits a machine-readable per-region representation (vector / browser-text / embedded-image / raster-fallback, per-region fidelity + warnings) for demo captures; still missing: a `redacted` representation class and a generic report for the portable (raster) path.

## H. Configuration & operations (§4, §26)

- `[x]` **Configurable operational limits UI** — the panel's advanced section exposes every limit: step ratio, scroll delay, max height, max passes, extra readiness delay, and readiness timeout (2–120 s).
- `[x]` **Capture presets** — save/load/delete named presets in the request panel (localStorage, this browser only); a preset replaces every setting below it.
- `[x]` **Readiness strategies in the UI** — strategy selector (load / DOM content loaded / network-idle / selector+CSS / manual) wired end-to-end: the demo engine honors each strategy (selector poll, resource-idle wait, layout-stability only for "load"), the request carries it, and the replay script emits the matching Playwright wait (`waitForSelector` / `networkidle` / `domcontentloaded` / timeout).
- `[x]` **Self-hosted capture service (ScreenshotOne replacement)** — `engines/` is a complete open-source screenshot API written **from scratch in Rust** (zero external crates): our own HTTP/1.1 server, RFC 6455 WebSocket client, Chrome DevTools Protocol client, JSON parser, PNG decode, base64/SHA-1/SSRF — the only external piece is the Chromium binary. `captured` serves ScreenshotOne-compatible `/v1/capture` GET/POST (PNG for now; webp/jpeg are roadmap), viewport/full-page, ad blocking, readiness strategies, motion freeze, per-request budgets, API-key auth + rate limiting, SSRF guard. Dockerfile + root `docker-compose.yml` (`docker compose up --build capture-service` — now builds `engines/`), 28 unit tests + three browser-gated end-to-end tests (`cargo test --test e2e_capture`: viewport, full-page, and the full REST path through auth/headers), docs in `engines/README.md` + `docs/self-hosted-capture-service.md`. The previous TS service (`capture-service/`, Hono + Playwright + sharp) is **deleted** — the full independence goal of the `independence-review` phase. The Convex action reads `CAPTURE_SERVICE_URL` / `CAPTURE_SERVICE_API_KEY` (Keys tab) instead of the paid ScreenshotOne key; the app surfaces setup guidance on missing-service. The `/api` page documents the endpoint and the one-command self-host setup. Human step: run the container (or deploy it) and paste the two env vars.

- `[x]` **Engine: in-process local engine** — `engines/src/desktop.rs` (`LocalEngine`): starts the capture server on a background thread via the new stoppable `http::serve_until_listener` (polled non-blocking accept + atomic stop flag, clean join on exit); `AppConfig`/`App::from_config` decouple server config from env (`App::from_env` unchanged for the standalone binary). Unit-tested: health, 404, start/stop.
- `[x]` **Tauri v2 shell** — `desktop/src-tauri/` (Cargo.toml, tauri.conf.json, `src/main.rs`/`src/lib.rs`): window config, `engine_url`/`engine_running`/`stop_engine` commands, engine started in `setup` with ephemeral-port fallback, graceful shutdown via `Drop`. Rust MSRV 1.77.2 (Tauri's) — the engine itself still builds on 1.75.
- `[x]` **Desktop-aware frontend** — `src/lib/capture/desktop.ts`: discovers the embedded engine via the Tauri IPC bridge (`window.__TAURI__`) and routes URL captures to it (same `/v1/capture` contract + same result shape as the Convex action, so `CaptureJob` swaps transparently via a new `EngineDeps.localCaptureUrl`). URL capture therefore works **offline** in the desktop app — no CAPTURE_SERVICE_URL, no key, nothing leaves the machine.
- `[x]` **Native OS screen/region capture (desktop)** — implemented in `engines/src/screen.rs`: per-OS backends using raw FFI (Windows BitBlt via GDI32, macOS CGWindowList via CoreGraphics, Linux XGetImage via Xlib), exposed as three HTTP endpoints (`/v1/screen/capture`, `/v1/screen/region`, `/v1/screen/bounds`) and three Tauri IPC commands (`capture_screen`, `capture_screen_region`, `screen_bounds`). The desktop app's header gains a "Capture Screen" button (visible only in the Tauri shell): clicking it shows a fullscreen Snagit-style overlay — dim scrim, crosshair, live dimension readout, Esc to cancel — the user drags a region, the native engine captures the screen pixels directly from the OS compositor (the overlay never appears in the result), and the cropped PNG is loaded into the editor as a full CaptureDocument. Both the engine unit tests and the desktop Tauri `cargo check` pass. `desktop/README.md` and `docs/native-apps.md` updated.

## L. Sandbox environments (capture isolation, per-OS)

- `[x]` **Cross-platform sandbox core** — `engines/src/sandbox.rs`: `SandboxConfig` (isolation level + resource limits + filesystem policy), `Sandbox` (enter → `SandboxGuard`), `SandboxGuard` (monitor, cancel, drop-cleanup). Three isolation levels: `None` (trusted local/demo), `Basic` (temp isolation + rlimits), `Full` (OS-level sandbox + network isolation). Zero external crates — all resource limits via raw FFI (Linux `setrlimit`, macOS `setrlimit`, Windows Job Objects).
- `[x]` **Per-OS enforcement backends** — Linux: `setrlimit` for AS, FSIZE, NOFILE, NPROC, CPU (seccomp-bpf + namespaces documented for the fork+exec model). macOS: `setrlimit` for FSIZE, NOFILE, NPROC, CPU (App Sandbox seatbelt when running as .app bundle). Windows: Job Object with memory/process/CPU limits via `CreateJobObjectW` + `SetInformationJobObject` + `AssignProcessToJobObject`.
- `[x]` **Sandbox-aware Chromium args** — `Sandbox::chromium_args()` generates per-level flags: Basic disables extensions/sync/background; Full adds disk-cache isolation and renderer process limits. Memory limit maps to V8 `--max-old-space-size`.
- `[x]` **Private temp directory lifecycle** — `Sandbox::enter()` creates `stitap-sandbox-{label}-{pid}` in the OS temp dir; `SandboxGuard::drop()` removes it. URL captures always get private tmp; screen captures and trusted operations can opt out.
- `[x]` **HTTP endpoints** — `GET /v1/sandbox/status` (active guard, violations), `GET /v1/sandbox/config` (effective configs for each capture type: url/screen/trusted).
- `[x]` **Tauri IPC** — `sandbox_config(capture_type)`, `sandbox_status()` commands; the desktop header shows a green "Sandboxed" / "Isolated" / "Open" badge reflecting the current isolation level.
- `[x]` **Frontend integration** — `getSandboxConfig()`, `getSandboxStatus()` in `desktop.ts`; sandbox badge in the Workspace header visible only in the desktop shell; sandbox config inspectable via the Settings panel.
- `[x]` **10 unit tests** — config defaults, trusted/url/screen presets, enter+guard lifecycle, status reporting, Chromium args per level, private tmp cleanup, isolation level str roundtrip, violation JSON serialization.
